# 迅雷集中监控与零速清理

当前版本已支持公开注册、多用户独立空间和 Docker 常驻运行。访问 `http://服务器IP:8765` 注册账号即可使用，新账号机器列表为空；各账号独立添加、管理自己的机器。现有部署的 4 台机器归属 `Likka` 账号。启动、备份和旧数据迁移见 [Docker 平台部署说明](docs/docker.md)。

程序运行在 Mac/Linux 上，通过 SSH 调用目标 Windows 迅雷已有的命名管道接口。对方无需安装 Python、常驻程序或操作面板。使用你提供的 CLI 中的协议，已在 10.126.126.103、迅雷 25.1.12.1624 上实测实时读取成功，无需重启迅雷。

## 早期单机使用说明

以下记录原单机工具的功能和验证情况。当前多用户平台请按 [Docker 平台部署说明](docs/docker.md) 操作；公开注册后的用户空间默认为空，网页不能关闭整个平台，自动清理请在登录后按机器设置。

### 双击操作

- `启动监控.command`：按已保存的每台机器设置启动；初始默认关闭自动清理，可在网页开启或关闭。
- `启动自动清理.command`：启用自动清理，默认每 15 秒采样，连续零速达到 10 分钟后重新检查并移除任务，固定保留文件。
- `关闭监控.command`：停止网页及定时采样，等待当前查询/操作结束。已发送的移除操作不能撤销。

启动后自动打开 http://127.0.0.1:8765 。在网页选择机器后，直接开启或关闭自动清理，无需重启；重复启动会被阻止。关闭浏览器不是关闭监控。也可在启动终端按 Control+C。

Mac 脚本用 caffeinate 防止空闲休眠；合盖、关机或断网仍会影响运行。服务器需要能连接各台电脑的内网 SSH，网页仅监听本机回环地址。

## 清理规则

必须同时满足：

1. 任务出现在 `CategoryManagerCategoryGetDownloadingTaskIds(-1)` 返回的当前下载列表。
2. `TaskManagerTaskGetTaskBase` 的实时状态为 5（正在下载），速度数值为 0。
3. 每次采样均满足条件，且持续达到 `idle_seconds`；任务身份和已下载字节数未变化。
4. 执行前在远端再次查询当前下载列表及任务状态，两次检查之间隔 250 毫秒；速度恢复、进入排队/暂停、名称/路径变化或已下载字节变化即跳过。

排队状态 3、暂停状态 7、等待/启动/完成/未知状态不累计零速时间。离开当前下载列表、读取失败、采样间隔超过两倍周期、速度恢复、任务消失或程序重启时重新计时。这里的“连续”按定时采样判断，无法捕捉两次采样之间极短的速度/状态变化；字节增长也会重置计时。

实际移除只调用 `TaskManagerTaskDeleteTask(id, false)`，参数固定为不删除文件。自动清理始终保留文件；前端手动操作另提供显式的删除文件选项。每台主机每轮最多移除一个任务，让队列有时间补上。

执行前写入 `.runtime/events.jsonl`，返回成功后检查任务不再存在。网络中断等导致结果不确定时，记录并禁止自动重试同一任务，重启后仍保留此保护。不要随意清空日志。任务状态可能在最终检查和接口执行间发生变化，接口未提供原子的条件删除保证。

## 验证范围

实时接口已确认将下载、排队和暂停分开：一次实测读取 344 个未完成任务，包括 50 个正在下载、293 个排队、1 个暂停。数量会随下载变化。旧数据库采样已不用于监控或清理。

计时、排队保护、复查跳过、调用异常不重试、记录持久化和启停已测试。七种手动操作已在 103 的独立测试下载任务上实测；暂停确认状态 7，保留文件模式确认 .xltd 文件仍在，删除文件模式确认 .xltd 和配置消失。详情见 [实机验证报告](docs/103-validation.md)。HTTP 测试文件结果不能覆盖每种 BT 多文件布局。

## 前端手动操作

与原 CLI 相比，现有程序增加集中网页面板、多机器配置、连续零速计时、操作预览和记录。现在补齐以下功能：

| CLI 命令 | 前端入口 |
|---|---|
| `pause zero` | 暂停零速任务 |
| `del 序号或ID` | 每行“移除·保留文件” |
| `delf 序号或ID` | 每行“删除文件” |
| `del zero` | 移除零速任务·保留文件 |
| `delf zero` | 删除零速任务及文件 |
| `del zero20` | 移除零速且进度 <20%·保留文件 |
| `delf zero20` | 删除零速且进度 <20% 及文件 |
| `q` | 平台版使用“退出登录”，停机由服务器管理员操作 |
| `show / find / n / p / refresh` | 详情、搜索、上下页、刷新所选机器 |

先选择机器，再点击批量按钮；预览列出匹配任务和保存位置，120 秒内确认执行。删除文件必须输入“删除文件”。只处理确认预览中的任务，不把新补入队列的任务继续纳入。批量操作不等待 10 分钟，按照点击时的当前零速状态筛选；每条执行前再次检查。

单条删除可用于暂停或排队任务，因为是用户明确选择；所有批量零速操作都排除排队任务。实际进度恰好 20% 或大小未知时，不匹配 zero20。显示的四舍五入百分比仅供阅读，筛选用原始字节数比较。

手动操作和自动清理按主机串行执行，页面显示逐条成功、跳过或结果未确认。结果未确认会停止该批次后续操作并锁定该任务，避免自动重试。退出服务会停止未发送的批量请求，已发出的操作无法撤销。

原 CLI 文件保留原样。实测发现其中暂停调用缺少状态参数，在 103 上会超时；本程序已改为 `TaskManagerTaskStopTask(id, 7)` 并确认状态。102 的 12.4.7.3858 当前接口测试失败，尚未支持；不要将 103 的结果视为所有迅雷版本兼容。

## 配置

推荐通过网页添加机器和调整自动清理。也可编辑 `config.json`，手工修改后重启：

- `mode`：旧配置的默认模式。每台机器的 `auto_enabled` 优先；网页开关保存到此字段。专用自动清理启动脚本仍会显式开启所有已配置机器。
- `poll_seconds`：默认 15，至少 5。
- `idle_seconds`：默认 600，至少为采样周期的两倍。
- `listen_port`：默认 8765。
- `hosts`：每个 id 唯一，填写 address、port、credentials_file；每台另有 `auto_enabled` 和 `idle_seconds`。网页添加的机器总是默认关闭自动清理。凭据文件第一行账号、第二行密码。

不同机器/版本缺少管道或列表接口时会报异常，不回退到数据库猜测状态。面板显示全部未完成任务，可筛选下载和排队；不显示已完成任务。

新增机器需先记录并核对主机密钥（替换 USER/HOST/PORT）：

```sh
ssh -o UserKnownHostsFile="$PWD/.runtime/known_hosts" -o StrictHostKeyChecking=ask -p PORT USER@HOST exit
```

程序拒绝未知或变化的主机密钥，凭据不返回网页。你提供的原始 CLI 保持不变；其中有内嵌凭据和删除文件功能，本监控不会导入或执行它。

## 安装与命令行

Python 3.10+，macOS/Linux：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python monitor.py --once       # 始终只读，即使配置为 auto
.venv/bin/python monitor.py             # 按配置启动
.venv/bin/python monitor.py --auto      # 自动清理
.venv/bin/python monitor.py --stop
.venv/bin/python -m unittest discover -s tests -v
```

## 网页设置与添加机器

1. 双击 `启动监控.command` 打开面板。
2. 点击机器卡片或下拉框选择机器。该机器的任务、操作记录、自动清理状态和时间会显示出来。选择“所有主机”只汇总查看，不支持批量操作或统一开启清理。
3. 在“自动清理设置”中修改分钟数，点击“开启自动清理”“关闭自动清理”或“保存时间”。设置立即生效并写入配置；开启/保存会重新计时，不把此前的观察时间立即算作删除依据。下次普通启动会恢复保存的开关，关闭服务不是关闭持久化开关。
4. 点击“添加机器”，填写名称、IP 和端口。选择复用已有机器的账号密码，或填写新账号密码。
5. 检查 SSH 密钥，核对显示的指纹后勾选确认，再点击“添加并检测迅雷”。密钥检查有效期为 120 秒，修改地址后需要重新检查。已有密钥变化时拒绝添加。
6. 添加后自动选择新机器。连接失败、凭据错误或版本不兼容会保留配置并显示异常；不会因此开启自动清理。当前支持在网页新增机器，修改已有机器的 IP/凭据或移除机器仍需编辑配置后重启。

新凭据保存在本项目 `.runtime/credentials/`，文件权限 0600，网页不回显。新增主机与自动清理设置写入当前实际使用的配置文件，包括 `--config` 指定的路径。未增加远端常驻程序。

本轮验证：5 项机器配置测试与 8 项自动清理保护测试通过，Python/JavaScript 语法检查通过。审批服务出现内部请求解析故障，完整回环 HTTP 测试与浏览器验证本轮未执行；此前的前端手动操作验证结果不代表本轮新增设置界面已做浏览器实测。

## 总览大盘与一键加速

启动后默认进入浅色“总览大盘”，可切换“任务管理”。大盘显示有效采样机器的总下载速度、在线数量、下载任务数、当前零速任务、速度趋势、任务分布和每台机器的速度卡片。点击卡片进入该机器的任务操作。

速度使用实时下载任务的 speed 求和，不包含排队任务。离线、读取失败、速度未知或超过 max(60 秒, 三倍采样周期) 未更新的机器不计入当前总速度，显示为未知而非 0。历史保留本次进程运行每台最近 240 个采样，服务重启后清空；历史图为当时有效机器的速度之和，部分机器离线时总量可能下降。

**一键加速**会立即对点击时已配置的所有机器执行一次 `del zero`，不等待自动清理的 10 分钟门槛，始终保留文件。最多同时检查 8 台；每台读取一次候选列表，执行前重新验证状态、速度和身份。只处理正在下载且实时速度为 0 的任务，排队/暂停任务不参与；不会把随后补入队列的新任务不断加入当前批次。

大盘展示各机器匹配、已移除、跳过、未确认及失败数量。运行中重复点击返回同一批次，不启动第二个批次。正在手动操作的机器可能被跳过并报告失败；一台连接失败不影响其他机器。执行结果未知时沿用既有的停止该机批次及禁止自动重试保护。退出服务停止尚未发送的操作，已发出的删除请求不可撤销。此功能释放下载名额，不保证下载资源一定提速。

观察模式只关闭定时自动清理，不禁用“一键加速”或手动操作。大盘刷新不会触发加速；只有点击按钮才执行。

### 控制台界面更新

界面采用固定侧栏、浅灰工作区、蓝色选中状态与紧凑按钮。左侧可直接选择机器，总览支持机器卡片／列表切换，每台卡片包含实时速度、速度趋势、任务分布条，以及任务管理、当前零速任务和自动清理设置快捷入口。

任务分布包含传输中、下载中零速、排队、暂停、其他及速度未知；全局以环图呈现，每台以分布条呈现。总下载速度同时展示在指标卡和趋势面板标题区。离线机器的当前数值显示为未知，历史曲线保留以便回看。

用户指定的视觉参考为 https://github.com/autobrr/qui ，本次读取仓库的网络请求因审批服务内部解析故障未执行，因此没有声称已核对其实际截图。已完成统计测试与模拟 DOM 渲染检查，尚未完成真实浏览器视觉验证。

## Docker 部署与网页登录

平台开放注册，不需要初始化码。注册后进入自己的空工作空间，机器、凭据、操作记录及后台监控按固定用户 ID 隔离。默认发布到所有 IPv4 网卡的 8765 端口。网页登录密码与各机器的 SSH 密码独立，账号设置仅影响自己的会话。

完整启动、停止、HTTPS、备份及旧数据迁移步骤见 [Docker 平台部署说明](docs/docker.md)。
