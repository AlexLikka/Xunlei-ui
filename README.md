# 迅雷集中监控与云盘加速 WebUI

通过 SSH 集中管理多台 Windows 电脑上的迅雷：查看下载状态、控制任务、查看回收站，以及把低速磁力任务转存云盘后创建本地下载。支持公开注册，各账号拥有独立的机器、凭据、设置和操作记录；新用户空间为空，不需要初始化码。

**本项目于 2026-10-29 冻结封档，不再主动维护。** 最终快照标签为 `archive-2026-10-29`。项目调用迅雷客户端内部接口，客户端升级可能导致接口失效。

## 迅雷版本与运行条件

| 项目 | 已验证情况 |
| --- | --- |
| Windows 迅雷 `25.1.12.1624` | 已实测实时任务、已完成、回收站读取及任务操作；云盘功能的条件与限制见下文 |
| Windows 迅雷 `12.4.7.3858` | 早期实测实时接口失败，不支持 |
| 其他迅雷版本、macOS 迅雷、迅雷 NAS 等 | 未验证，不保证兼容 |
| 平台运行环境 | Linux Docker / Compose，或 macOS / Linux + Python 3.10 及以上；镜像使用 Python 3.12 |
| 目标电脑 | Windows，已启用 SSH，平台能连接其 SSH 端口，迅雷客户端正在运行 |
| 云盘功能额外条件 | Windows PowerShell 5.1、交互用户保持登录，迅雷已登录云盘；允许上传执行模块并登记一次性计划任务 |

普通监控通过 SSH 调用迅雷现有命名管道，不需要在目标机安装 Python。云盘功能会将配套 PowerShell 模块部署到目标用户的 `%LOCALAPPDATA%/ThunderWebUI/`，通过一次性计划任务脱离 SSH 执行。迅雷登录令牌留在目标电脑。

## 功能

- 总览大盘：多机速度、在线状态、任务分布、速度历史；任务搜索、分页和详情。
- 查看未完成、已完成及迅雷内部回收站；回收站独立统计，不参与普通暂停、删除或自动清理。
- 按账号添加机器、修改名称 / 地址 / SSH 端口和凭据、核对主机密钥、删除连接配置。
- 启动全部未完成任务、暂停零速任务、移除并保留文件，或明确确认后删除任务及文件。
- 可选连续零速自动清理：默认关闭，默认观察 10 分钟，仅移除仍在下载且持续零速的普通任务，固定保留文件。
- 一键加速、回收站单项 / 批量转存、云盘资源下载、已有下载核对和归档。
- 后台预览和执行进度、用户空间隔离、持久化操作记录与结果不明时禁止自动重发。

预览有效期为确认前 15 分钟，已受理任务不受此时限影响。修改机器配置会使旧预览失效；删除机器仅移除当前账号的连接配置，不删除远端任务或文件。

## Docker 快速开始

```sh
git clone https://github.com/AlexLikka/Xunlei-ui.git
cd Xunlei-ui
sudo docker compose up -d --build --wait
```

访问 `http://服务器IP:8765`，注册账号并添加自己的机器。默认发布到所有 IPv4 网卡，防火墙 / 安全组需放行 TCP 8765；私网目标需要平台服务器已有可用路由。添加机器前核对网页显示的 SSH 主机密钥指纹。

```sh
sudo docker compose ps
sudo docker compose logs --tail=100 thunder
sudo docker compose stop                 # 停止服务，保留数据
sudo docker compose up -d --wait          # 再次启动
```

账号、机器、凭据及操作记录持久化在命名卷 `thunder-tool_thunder-data`，不会包含在 Git 仓库或镜像中。不要使用 `docker compose down -v` 删除数据卷。完整的备份、迁移、HTTPS 和监听设置见 [Docker 部署说明](docs/docker.md)。

Compose 默认使用 `unless-stopped` 重启策略。封档时管理员可额外执行 `docker update --restart=no thunder-tool-thunder-1`；之后主动执行 `compose up` 可能按 Compose 配置恢复重启策略。

## 一键加速的实际行为

默认选择正在下载、实时零速、进度严格低于 20% 的普通任务；排队、暂停、回收站及原生云盘下载不参与大盘一键加速。回收站需使用独立转存入口。

1. 保存原任务及 BT 文件选择，自动创建云盘专属根目录、批次目录和任务目录，无需填写目录 ID。
2. 普通任务重新核对身份后移除原任务，保留本地文件，再提交云盘缓存。**缓存失败不会自动恢复原下载任务。**
3. 默认等待 5 分钟，检查一次各项缓存。每个种子独立处理，整项缓存完整且原 BT 清单核对通过后才创建本地下载；同批失败项不会阻塞已完成项。
4. 默认按原保存位置生成“云盘转存”子目录并保留任务 / 相对目录结构，可在高级设置覆盖本地保存路径。“只缓存”不创建本地下载。
5. 检测到本地实际下载字节、速度或完成状态后，将对应云盘资源移入“已下载”目录。**此目录表示下载已启动 / 已归档，不表示本地已经下载完成；程序没有下载完成后永久删除云盘资源的逻辑。**

首次检查时缓存未完成，需稍后使用“云盘资源下载”，并填写目标 Windows 的绝对下载路径。每个种子必须整项缓存完整，尚未实现种子内部分文件先下载。启动核对约 45 秒，排队较久的任务可稍后使用“核对已有下载并归档”。

新确认的回收站转存逐项等待缓存成功、完整性和身份核对通过后，仅清理对应回收站记录，保留本地文件与云盘资源。每 5 分钟检查一次，最长 24 小时；失败、未完成、身份变化或结果不明的条目保留。历史请求不会自动补删。“只缓存”同样安排成功后的回收站记录清理。

**停止 Web 容器不会取消已提交的 Windows 计划任务或迅雷下载。** 具体接口、阶段和异常处理见 [云盘集成说明](docs/cloud-integration.md)。

## 自动清理与执行保护

自动清理仅统计当前下载列表中状态为 5、速度为 0 且没有字节增长的任务；默认采样 15 秒、连续零速 600 秒。排队、暂停、读取失败、采样中断或任务身份变化都会停止 / 重置计时。执行前再次核对下载列表、身份与状态，每机每轮最多移除一项，调用 `TaskManagerTaskDeleteTask(id, false)`，不删除本地文件。

修改动作先写入操作记录，网络中断等造成结果不明时不会盲目重试。请保留运行记录以便核对，不要通过清空记录绕过保护。手动删除文件需要单独确认；观察模式仅关闭定时自动清理，不禁止用户确认的手动操作或云盘转存。

## 资源占用与已知限制

面向 2 核 / 2 GB 主机限制并发：共享采样池 2、预览池 2、远端 I/O 最多 4 个连接；手动操作每批 8 项复用连接，启动最多并发 2 批，暂停 / 删除按顺序执行。Compose 默认内存上限 384 MB、CPU 上限 1 核、进程 / 线程上限 128，可通过环境变量调整。

大状态响应支持 gzip，网页状态请求等待上限为 60 秒，避免慢速外网加载大量记录时提前中止。远端网络、命名管道和云缓存仍可能很慢；“已受理”只表示提交成功，不表示缓存或下载完成。速度历史仅保留本次进程内的近期采样，重启后清空。

已验证云盘建单、调度、状态回写及受控回收站清理；不同资源仍可能缓存失败、空间不足或文件清单不完整，不保证任意种子都能加速。测试与模拟断言不能替代任意资源的完整端到端验证。

## 本地运行与测试

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python monitor.py
# 停止当前数据目录对应的本地服务：
.venv/bin/python monitor.py --stop
# 无远端网络的 Python 回归测试：
.venv/bin/python -m unittest discover -s tests -v
```

默认数据目录为项目目录，可设置 `THUNDER_DATA_DIR` 独立保存；`THUNDER_BIND` 默认 `0.0.0.0`，`THUNDER_PORT` 默认 `8765`。macOS 可使用 `启动监控.command` 和 `关闭监控.command`；自动清理在登录后的网页按机器开启。旧全局 `--auto` 模式不适用于多用户平台。

2026-10-29 封档检查使用 Python 3.12，**86 项 Python 测试全部通过**。`tests/browser/` 为可选 Playwright / Chromium 交互回归，`tests/remote/` 为 Windows PowerShell 模拟断言；不属于上述 Python 单元测试命令。需要账号的浏览器脚本从环境变量读取测试凭据，不包含实际账号。
