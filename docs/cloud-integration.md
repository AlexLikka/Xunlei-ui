# 云盘转存与一键加速（最终封档说明）

最终状态：2026-10-29。配套接口在 Windows 迅雷 `25.1.12.1624` 上验证。实现参考本地新版 CLI 及其控制模块，仓库只发布整理后的 PowerShell 执行模块与协议，不包含原始 CLI 内的凭据、机器配置或迅雷登录令牌。

## 网页入口与默认目录

| 入口 | 用途 |
| --- | --- |
| 总览“一键加速” | 预览所有机器符合条件的零速普通任务并提交转存 |
| 任务管理“转存零速任务” | 转存所选机器的普通零速任务 |
| 回收站列表 / 详情“转存云盘” | 单项转存原链接；机器工具栏可批量转存 |
| “云盘资源下载” | 查看完整缓存资源，确认后创建本地下载，需填写 Windows 绝对路径 |
| “云盘转存与状态” | 查看资源、批次、下载与清理结果，安装 / 更新远端模块，核对已有下载并归档 |

默认进度门槛严格低于 20%，缓存等待 5 分钟。可指定只缓存、等待 0–1440 分钟及目标 Windows 保存路径。大盘一键加速排除排队、暂停、回收站和原生云盘下载。

一键加速、普通转存和回收站转存会自动创建工作空间专属云盘根目录、批次及任务子目录，无需输入目录 ID。默认本地下载目录基于原保存位置，增加“云盘转存”及任务目录并保留相对目录结构。可在折叠的高级设置中覆盖本地路径。

独立“云盘资源下载”的本地路径必填；其云盘目录 ID 留空时读取工作空间专属目录。修改参数必须重新预览；预览有效期仅限制确认前 15 分钟，已受理的任务不会因预览到期而中止。

## 执行顺序与边界

1. 保存原任务、来源链接、BT 文件清单及勾选项，创建专属云盘目录。
2. 普通下载重新核对当前下载列表、任务身份、零速与进度，移除原任务但保留本地文件，再提交缓存。**缓存失败不会自动恢复原任务。** 回收站转存不先恢复任务，成功缓存后按下节规则清理记录。
3. 使用目标机已登录迅雷的云盘 SDK 提交缓存。响应不明时保留待核对状态，不自动重发缓存或建单。
4. 非“只缓存”请求等待指定时间，由 Windows 一次性计划任务检查一次。每个种子独立判断，只有整项云缓存完整且原 BT 清单核对通过才进入下载；同批其他种子失败不会阻塞成功项。
5. 使用 `batchCreateDownloadTaskWithFiles` 创建迅雷原生云盘下载，按云盘文件 ID 核对建单，保留 BT 文件选择及相对目录。原生云盘下载排除在旧零速自动清理之外。
6. 观察到本地实际字节、速度或完成状态后，将相应云盘资源移入归属已核对的“已下载”目录。

**“已下载”表示下载已启动 / 已归档，不代表本地已经完成；没有下载完成后永久删除云盘资源的逻辑。** 最初的启动核对窗口约 45 秒，超过窗口才开始的排队任务可手动“核对已有下载并归档”；该操作不新建下载，也不重新提交缓存。

下载阶段只检查一次缓存。届时未完整的资源需要稍后手动使用“云盘资源下载”，不存在持续自动等待到完成的下载调度。每个种子必须整项缓存完整，尚未实现种子内部分文件先下载。存储空间、缓存服务、文件清单、目标盘符和用户权限均可能影响结果；“提交处理完毕”不是下载完成。

## 回收站成功后清理

新版网页预览明确传入并冻结 `cleanup_recycle=true`，随确认请求持久化。普通转存和未携带此标记的历史请求不会追加回收站清理。

云盘明确返回文件 / 任务 ID 后记录缓存受理状态；受理本身不会触发删除。仅当 `Get-CompleteSnapshot` 验证本种子完整缓存、云盘归属和原 BT 清单后，才允许清理对应记录。各种子独立检查。

清理前重新读取回收站视图 3，逐项核对原任务 ID、URL、名称、保存路径、大小、类型与 recycleTime；已恢复或发生变化时保留。先持久化清理意图，再调用 `TaskManagerTaskDeleteTask(id,false)`，复查对应记录已消失。结果不明时禁止自动重发。

仅清理明确的单个回收站记录，不清空回收站，不删除本地文件或云盘资源。失败、未完成、身份变化和结果不明的条目保留，并显示等待、已清理、记录变化、待核对或到期状态。

首次远端修改前登记专属 `ThunderWebUI-RecycleCleanup-<requestId>` 计划任务，使用同一互斥锁，每 5 分钟检查一次，最长 24 小时；工作完成或到期后注销本请求的计划任务。“只缓存”同样安排此检查，不因此创建本地下载。此检查独立于下载阶段的一次性缓存检查。

## 后台运行、隔离与异常处理

每个平台账号独立保存配置、SSH 凭据、提交记录与状态。目标机模块保存在 `%LOCALAPPDATA%/ThunderWebUI/<工作空间与机器散列>/`，执行代码按内容版本存放，避免更新破坏已提交请求。已有外部 CLI 的状态和计划任务不被接管。

Web 后端先原子写入提交意图，再上传输入并启动交互用户的一次性 Windows 计划任务；目标用户须保持登录，迅雷须运行且已登录云盘。关闭网页、SSH 或 Web 容器不会取消已经登记的远端工作，Web 重启后会重新核对历史请求。删除机器配置也不会撤销已登记的工作。

原任务交给转存链路后，旧自动清理持续排除它。网络超时显示结果待核对，不自动重复删除、缓存或建单。请保留 Web 数据卷和目标机的版本化代码、输入及运行记录，不要通过清空状态直接重试。回退 Web 代码同样不会撤销远端动作。

## 并发与低内存部署

- 全局共享采样池 2、预览池 2、预览等待队列最多 8；相同未完成预览复用。
- 远端 I/O 最多 4 个连接，一键加速跨机器最多 2 台并发提交，每台机器云盘修改串行。
- 候选优先使用 60 秒内的近期采样；修改动作始终再次核对远端真实状态。
- 手动操作每批 8 项复用连接；启动最多 2 批并发，暂停 / 删除串行，结果不明时停止后续动作。
- Compose 默认 384 MB 内存、1 核 CPU、128 个进程 / 线程，并设置 `MALLOC_ARENA_MAX=2`。

预览立即返回后台编号，页面轮询进度。云盘提交请求等待上限 15 秒；收到受理响应后，面板刷新独立执行。状态快照支持 gzip，网页状态请求上限 60 秒。限额不会缩短云服务本身的缓存时间。

`tests/browser/` 包含机器编辑、回收站清理说明及云盘交互回归；测试使用隔离接口数据或拦截非空执行请求。可选浏览器 / 远端测试不包含在 Python 单元测试命令中。历史只读接口调研见 [云盘链路研究](cloud-workflow-research.md)。
